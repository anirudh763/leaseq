# Environment configuration

LeaseQ reads service settings from its process environment. For Docker Compose, copy the root `.env.example` to `.env`; `scripts/up.sh` fills blank or missing `LEASEQ_API_TOKEN` and `LEASEQ_APP_PASSWORD` values with random values, preserves valid existing values, sets mode 600, and uses shell exports ahead of the file. The application password must be at least 32 hexadecimal characters so it can be embedded safely in the internal DSN. Do not commit `.env`.

`LEASEQ_API_TOKEN` is required for authenticated API requests. Compose builds the application DSN from `LEASEQ_APP_PASSWORD` and the internal `postgres` hostname. A one-shot bootstrap service uses the local cluster administrator to provision the ordinary application role; API/worker containers do not receive that administrator credential. Other settings in the example (database URL, body/rate budgets, public-read mode, retry backoff and count-cache age) apply to directly launched processes; adding them to Compose's `.env` alone does not pass them into containers. To configure a container, declare the chosen setting explicitly in that service's `environment` section or a Compose override. A container database URL must use the reachable Docker service hostname, rather than host-loopback `127.0.0.1`. Leave optional settings unset to use the code defaults.

The optional n8n configuration is separate at [integrations/n8n/.env.example](../integrations/n8n/.env.example). It does not connect LeaseQ to n8n or enable workflows. Keep API keys in n8n's credential store, not workflow `$env` expressions or browser code.
