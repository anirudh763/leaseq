Optional Supabase workspace sync

LeaseQ has no hosted cloud workspace by default. This is a reference connector for a Supabase project that you control. No project, account, table, or key was created for this app.

Setup boundary

  1. Create a Supabase project and an account using Supabase’s own account controls.
  2. Run the reviewed SQL schema in your project’s SQL editor.
  3. Enter the project origin and publishable/legacy anon key in LeaseQ Settings. Secret and service_role/admin keys are rejected in browser code.
  4. Sign in to Supabase, select the local categories to sync, and consent before each read/write.

Data and conflict handling

Only selected local theme preferences, submit drafts, or a saved simulator example can be sent. Live jobs, queue responses, API tokens, local password verifiers, and mutation commands are excluded. The token for Supabase stays in page memory and is separate from LeaseQ’s shared API bearer.

Each account gets one row protected by row-level security. Revision-checked updates preserve a newer remote revision as a conflict; choose restore or replace explicitly. Deletion creates a revisioned tombstone and leaves local data intact. Network retries are bounded to safe reads; writes are not silently retried.

This connector has only been verified against an owned local protocol receiver. No real Supabase project, cross-device session, RLS deployment, recovery policy, or third-party availability has been tested. Browser-local profiles are not cloud identity; Supabase sync does not authorize LeaseQ API jobs.
