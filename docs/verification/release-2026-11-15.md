# LeaseQ verification — November 15–16, 2026

The full r10 Python suite passed **240 tests with no skips**, using real PostgreSQL fixtures, subprocess workers, Chrome and axe. One existing Starlette/httpx deprecation warning remains. This is finite local verification, not a cloud capacity or availability guarantee.

## Authorization and update safety

Token validation now uses the configured API origin. Changing that origin invalidates pending authorization, and an old reply cannot authorize a different target. Tokens remain in page memory. The browser safety state counts every API request through response-body processing, including ordinary mutations and token validation; requests have bounded timeouts. A service-worker update requires affirmative replies from every open client. A missing reply blocks activation.

A new browser regression failed on the original defects, then passed all 22 assertions. Independent probes separately reproduced and rechecked the same failures. These transport-failure tests intercept dummy credentials and responses before any queue write; they do not substitute for the real database and worker tests. Pinned font responses accept the slim server's generic MIME only with their exact required SHA-256 digest. Client and worker release markers agree, allowing old caches to prune safely.

## Worker recovery

The worker retries a failed fenced completion once, with the same job, result and lease token. It does not rerun the handler. The unfenced negative control remains unchanged. Four new real PostgreSQL/API/worker cases cover a terminated completion connection, a committed transaction whose acknowledgement is lost, a bounded second failure and exclusion of the unfenced path. They and the existing two chaos cases passed.

An additional real container check stopped and started PostgreSQL while all four workers kept running. Readiness recovered in 0.54 seconds. A fresh job with **one allowed attempt** then completed in 0.289 seconds, with one completion event and one effect row. Before the fix, the observed job needed three attempts and about 60.37 seconds. These are observations on this Mac and workload, not a universal recovery deadline.

## API and container checks

Operational GET reads bound pool acquisition to two seconds and SQL statements to five seconds. An occupied pool returned sanitized 503 in 2.003 seconds; an actual `pg_sleep` query returned 503 in 5.015 seconds, then reads recovered. These limits do not bound every network or end-to-end failure. Programming errors remain visible. Process liveness is separate from database readiness. Credentials and job contents are excluded from request logs and metric labels.

The API and workers run as UID 10001 with read-only roots, dropped capabilities, no-new-privileges and bounded resources. The five-app container acceptance passed 71 checks, including real database loss, recovery and preservation of the existing job count. A separate backup/restore exercise preserved 33 jobs and the append-only trigger in a scratch database; those historical fixtures were cleaned up without deleting the retained application volume.

Direct browser checks covered 320, 768 and 1440 pixels, keyboard focus, exact Pause/Resume action names, actual polling, empty/error states and axe scans with no reported violations. Actual macOS VoiceOver navigation/action samples were recorded earlier. Repeating the final native action was blocked after macOS locked; browser keyboard checks still passed. Automated accessibility tests are not a human usability study or conformance certificate.

## Release scope

The complete 100-case mutation campaign runs in an isolated source/database copy against the frozen release. Its final result and harness-anchor changes are reported separately; historical or provisional attempts never count as a passing campaign. Current-head CI and merge remain distinct gates.

The free Pages site runs a labeled browser simulation. A live API requires an authorized server; no paid hosting, production failover, hosted identity provider or unmeasured production queue capacity is claimed.
